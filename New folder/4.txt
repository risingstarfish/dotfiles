The biggest could be the error channel's shape. A status int/enum versus a small struct carrying a std::string and int status code. The better choice is enum because it is a single value and can be used to represent both the error code and the error message (through enum_to_string function).  It is also exception free unlike strings. The >MAXLEN case must be rejected with a clear diagnostic instead of overflowing or truncating. const char* pdbErrStr(PdbErr) should be a free function in a small PROT/PDB namespace mirroring the repositories style. Because none of the four named traps (Trace, 25 member new[]/delete[], -fopenmp, and ofstream Display write) there should be a description as to why.
